# হিসাব — দোকানের খাতা ও গুদাম

দোকান বা ছোট ব্যবসার খাতা আর গুদাম, একসাথে। কাগজের মেমোর খাতা যা করত তার ডিজিটাল রূপ,
কিন্তু তিনটা বাড়তি জিনিস সহ:

- **স্টক আপনাআপনি হিসাব হয়** — আলাদা করে গুদামের খাতা রাখতে হয় না
- **কোনো এন্ট্রি মোছা যায় না** — হিসাব জালিয়াতি ঠেকাতে, ডেটাবেসের স্তরেই আটকানো
- **ছয়জন একসাথে কাজ করতে পারে** — কে কী করল সব লেখা থাকে

পুরো অ্যাপ বাংলায়, ফোনের জন্য বানানো।

## চালু করবেন যেভাবে

### ১. কোড নামান

```sh
git clone https://github.com/Muntasirifraim00/Hisab-Lenden.git
cd Hisab-Lenden
npm install
```

### ২. Supabase প্রকল্প বানান

[supabase.com](https://supabase.com) থেকে একটা নতুন প্রকল্প খুলুন, তারপর:

**ক) ডেটাবেস তৈরি করুন** — `supabase/migrations/` এর SQL ফাইলটা প্রকল্পের
**SQL Editor**-এ চালান। (অথবা Supabase CLI থাকলে `supabase db push`।)

**খ) ইমেইল যাচাই বন্ধ করুন** — **Authentication → Sign In / Providers → Email**-এ গিয়ে
*Confirm email* বন্ধ করুন। এই অ্যাপে লগইন হয় `ismail@hisab.local` ধরনের ঠিকানায়, যেখানে
যাচাই-মেইল পাঠানো যায় না। বন্ধ না করলে প্রথমবার অ্যাকাউন্ট তৈরি হবে ঠিকই, কিন্তু ঢোকা যাবে না।

**গ) চাবি বসান** — `.env.example` কপি করে `.env` বানান:

```sh
cp .env.example .env
```

`VITE_SUPABASE_URL` আর `VITE_SUPABASE_PUBLISHABLE_KEY` পাবেন প্রকল্পের
**Settings → API** পাতায়।

### ৩. চালান

```sh
npm run dev
```

`http://localhost:5173` খুলুন। ছয়টা নামের একটা বাছুন, একটা পাসওয়ার্ড দিন —
প্রথমবারেই অ্যাকাউন্ট তৈরি হয়ে যাবে। **সেই পাসওয়ার্ডটাই পরে লাগবে।**

### ৪. প্রথম কাজ

১. **পণ্য ও ক্যাটাগরি** পাতায় গিয়ে পণ্য যোগ করুন — ক্রয়মূল্য আর ওপেনিং স্টক দিতে ভুলবেন না
২. নিচের ➕ বোতাম দিয়ে প্রথম হিসাব লিখুন

## AI স্ক্যান (ঐচ্ছিক)

মেমোর ছবি তুললে AI পড়ে তারিখ, টাকা, পরিশোধ, পার্টির নাম ও বিবরণ আপনাআপনি ভরে দিতে পারে।
চালু করতে `.env`-এ [console.anthropic.com](https://console.anthropic.com) থেকে নেওয়া চাবি বসান:

```
ANTHROPIC_API_KEY="sk-ant-..."
```

চাবি না দিলেও পুরো অ্যাপ স্বাভাবিকভাবে চলবে — শুধু স্ক্যান বোতামটা "চালু নেই" বলবে।

> ⚠️ AI ভুল করতে পারে, বিশেষ করে হাতে লেখা মেমোয়। সবসময় মিলিয়ে নেবেন।

## গুরুত্বপূর্ণ নিয়ম

### বাকি — একটা নিয়ম মনে রাখতে হবে

| পরিশোধিত ঘরে | ফলাফল |
| --- | --- |
| খালি রাখলে / ০ | হিসাব চুকে গেছে ধরা হয় → বাকি ০ |
| আংশিক (যেমন ৫০০) | বাকি = মোট − ৫০০ |
| পুরো টাকা | বাকি ০ |

অর্থাৎ কিছু না লিখলে "সব দেওয়া হয়ে গেছে" ধরা হয়। বাকি রাখতে চাইলে আংশিক অঙ্কটা লিখুন,
অথবা ফর্মের **"কিছুই দেইনি"** বোতামটা চাপুন।

### স্টক — FIFO

যে মাল আগে কিনেছেন সেটা আগে বিক্রি হয়েছে ধরা হয়। যেমন হাতে ১০ লিটার তেল @ ৳১০০,
পরে আরও ৫ লিটার @ ৳১২০ কিনলেন। ১২ লিটার বিক্রি করলে ক্রয়মূল্য হবে
`১০ × ৳১০০ + ২ × ৳১২০ = ৳১,২৪০`। দাম ওঠানামা করলেও এভাবেই আসল লাভ বেরোয়।

স্টকে যা নেই তার বেশি বিক্রি করলে আটকায় না, কিন্তু চিহ্নিত করে রাখে — স্টক পাতায়
ঋণাত্মক দেখাবে, যাতে ভুলটা চোখে পড়ে।

### ভুল হলে

এন্ট্রি মোছা যায় না, টাকা-তারিখ বদলানো যায় না। শুধু **বিবরণ** বদলানো যায়, তা-ও প্রতিবার
লগ হয়। ভুল এন্ট্রি বাদ দিতে **বাতিল / সংশোধনী** দিন — একটা উল্টো এন্ট্রি তৈরি হবে, মূলটা
খাতায় থেকে যাবে প্রমাণ হিসেবে, আর স্টকে উল্টো প্রভাব পড়বে।

## ভেতরের কাঠামো

TanStack Start (React ১৯) + Supabase (Postgres) + Tailwind ৪।

**ডেটাবেসের ১০টা টেবিল:** `invoices` · `invoice_items` · `invoice_payments` ·
`invoice_receipts` · `invoice_expenses` · `invoice_detail_edits` · `products` ·
`product_categories` · `stock_lots` · `stock_moves`

সবচেয়ে জরুরি নকশার সিদ্ধান্ত: **কোনো টেবিলে INSERT / UPDATE / DELETE পলিসি নেই।**
সব লেখালেখি হয় `SECURITY DEFINER` RPC ফাংশনের মধ্য দিয়ে, যেগুলো এক ট্রানজেকশনে
ইনভয়েস + পণ্যের সারি + স্টক একসাথে লেখে। তাই —

- মাঝপথে নেট কাটলে অর্ধেক লেখা হয়ে থাকে না
- "ইনভয়েস আছে কিন্তু স্টক কমেনি" ধরনের গড়মিল সম্ভবই নয়
- FIFO ক্রয়মূল্য ও লাভ ডেটাবেসেই হিসাব হয়, অ্যাপ থেকে পাঠানো যায় না
- অ্যাপ হ্যাক করলেও এন্ট্রি মোছা বা টাকা বদলানো যাবে না

অ্যাপটা `/hisab` ঠিকানায় থাকে; মূল ঠিকানা `/` সেখানেই পাঠিয়ে দেয়।

### ডেটাবেসের যুক্তি পরীক্ষা

মাইগ্রেশনটা যেকোনো Postgres ১৬-তে চালিয়ে FIFO, অগ্রিম ক্রয়, বাতিল/সংশোধনী ও
অপরিবর্তনীয়তা পরীক্ষা করা যায়। `auth.uid()`, `auth.role()` ও `storage.*`-এর নকল
বানিয়ে নিলেই চলে — Supabase লাগে না।
